## Findings

### B-1 — Warning: marketing-pages Integration Contract claims a `/stage` ↔ `/services` cross-link that exists in only one direction

- **Artifact/section:** `blueprints/features/marketing-pages.md`, Integration Contracts ("Stage and Services sections cross-link (`/stage` ↔ `/services`) via `Link` inside `Content` copy").
- **Severity:** warning (unsupported claim as written)
- **Evidence:** The services→stage direction exists: the Services page's Studio section links to `/stage` (`app/services/page.tsx:42`). The stage→services direction does not exist anywhere: the stage page's only `next/link` usage is its closing CTA to `/contact` (`app/stage/page.tsx:196`), and its floor-plan link is a plain `<a>` to the PDF (`app/stage/page.tsx:151-157`). The home page's Stage and Services teaser sections each link to their own page (`app/page.tsx:45, 90`) — that is not a cross-link between the two routes. No requirement asks for stage→services (AC-MKTG-002 has no such criterion; AC-MKTG-003.3 covers services→stage only), so the blueprint exceeds both the code and the approved requirements.
- **Recommendation:** Reword to match observed behavior, e.g. "the Services page's Studio section links to `/stage`; the home page's Stage and Services teaser sections link to their respective pages."
- **Required next state:** corrected wording in `blueprints/features/marketing-pages.md` (or owner acknowledgment), then the artifact set can be finalized.

### B-2 — Warning: seo-discoverability ADR-001 says metadata consumes the readiness report's buckets; `generateMetadata` re-implements the rule inline

- **Artifact/section:** `blueprints/features/seo-discoverability.md`, ADR-001 ("sitemap and metadata consume its buckets rather than re-implementing rules").
- **Severity:** warning (architectural mechanism claim not supported by code)
- **Evidence:** The sitemap does consume the report: `app/sitemap.ts:16-18` calls `getProjectReadinessReport(projects)` and filters by the `indexable` bucket. The metadata path does not: `app/projects/[slug]/page.tsx:37` computes `isIndexable = project.publicationState === "indexable" || project.publicationState === "publishable"` inline, and that file never imports `getProjectReadinessReport`. The rule's semantics are identical in both places (the Key Contract "applied identically in `generateMetadata` robots and sitemap filtering" is accurate in effect), but the ADR's mechanism claim — one implementation consumed by both — is false: the gating rule currently has two implementations.
- **Recommendation:** Reword ADR-001 (e.g. "the sitemap consumes the report's buckets; `generateMetadata` applies the same indexability rule inline") or record the duplication as a known follow-up candidate. Making `generateMetadata` actually consume the report would be a code change for a future initiative, not a blueprint fix.
- **Required next state:** corrected wording in `blueprints/features/seo-discoverability.md` (or owner acknowledgment), then the artifact set can be finalized.

### B-3 — Note: project-detail ImageBlock enumeration omits the `intrinsic` aspect ratio

- **Artifact/section:** `blueprints/features/project-detail.md`, Feature-Specific Components (ImageBlock: "aspect-ratio (video/square/portrait)").
- **Severity:** note (incomplete enumeration; not inaccurate for the three named options)
- **Evidence:** The catalog type and the component both define four options: `aspectRatio?: "video" | "square" | "portrait" | "intrinsic"` (`constants/projects.ts:54`, `components/project/ImageBlock.tsx:10`). `intrinsic` currently maps to `aspect-video` (`components/project/ImageBlock.tsx:28`), so behavior is unchanged today, but the blueprint omits a legal catalog value.
- **Recommendation:** Add `intrinsic` to the enumeration the next time the blueprint is revised. No correctness impact.
- **Required next state:** none blocking; optional precision fix.

### B-4 — Note: technical-context remnant inventory omits two unused remnants (`VideoPlatform` type; four unreferenced video records)

- **Artifact/section:** `blueprints/technical-context.md`, Architectural risks and unknowns (unused remnant components list).
- **Severity:** note
- **Evidence:** (1) `constants/projects.ts:8` exports `type VideoPlatform = "local" | "mux"` with no references anywhere else in the codebase (searched all `.ts`/`.tsx`/`.mjs`/`.mts`). (2) `videos/` contains five next-video records, but only `videos/placeholder.mp4.json` is imported (`components/project/VideoBlock.tsx:5`); the four project-named records (`future-iq.mp4.json`, `future-iq-bts.mp4.json`, `polica-wasted-me.mp4.json`, `rba-awit.mp4.json`) are unreferenced — all four catalog projects use Mux playback IDs, not local sources. The risk list covers only the four user-confirmed remnant files.
- **Recommendation:** Optionally extend the remnant inventory (or fold both into the existing remnant-removal follow-up candidate). Harmless to leave as-is.
- **Required next state:** none; optional precision fix.

### B-5 — Note: readiness "buckets" are cumulative tiers, not a partition — `fixtureValid` lists every catalog slug

- **Artifact/section:** `blueprints/features/seo-discoverability.md`, Feature-Specific Components (getProjectReadinessReport: "Classify projects into fixtureValid / indexable / publishable buckets").
- **Severity:** note (mirrors the approved requirement's wording; semantics could mislead)
- **Evidence:** `utils/projectReadiness.ts:61-64` pushes every project's slug into `fixtureValid` unconditionally; `indexable` receives slugs whose state is not `fixture-valid`; `publishable` receives slugs whose state is `publishable`. A `publishable` project therefore appears in all three arrays. Only `indexable` is consumed downstream (`app/sitemap.ts:16-18`). The phrasing "classify into buckets" (identical to approved AC-SEO-005.3) can be read as a partition, which the code is not.
- **Recommendation:** Optional precision when next revised: "fixtureValid lists every catalog slug; indexable/publishable are tier supersets." No change required — the approved requirement uses the same wording.
- **Required next state:** none; approved as-is.
